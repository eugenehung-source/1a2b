# 1A2B 每日猜數字 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一個手機與桌機皆可完整遊玩的 1A2B 猜數字網頁（每日挑戰＋自由練習＋筆記盤＋統計＋分享），部署在 GitHub Pages。

**Architecture:** 無建置的 ES modules 靜態網站。四個純邏輯模組（`game`／`daily`／`stats`／`share`）以 Vitest 垂直 TDD 開發；`storage.js` 包 localStorage；`ui.js` 只負責 DOM 與事件，於瀏覽器實測驗收。

**Tech Stack:** HTML／CSS／JavaScript（ES2022 modules）、Vitest（唯一 devDependency）、GitHub Actions、GitHub Pages。

**Spec:** `docs/superpowers/specs/2026-10-14-1a2b-game-design.md`

## Global Constraints

- 無建置步驟；`index.html` 直接以 `<script type="module" src="src/ui.js">` 載入。
- `package.json` 的 devDependencies 只有 `vitest`；`"type": "module"`；`"test": "vitest run"`。
- 答案：0–9、不重複、允許 0 開頭。
- 每日：4 位數、10 次；台灣時間（UTC+8）00:00 換題；上線日為 #1。
- 練習：簡單 3 位／8 次、普通 4 位／10 次、困難 5 位／12 次。
- 介面只有繁體中文；頁面標題「1A2B 每日猜數字」；系統字型；深淺色跟隨 `prefers-color-scheme`。
- 版面最大寬度 480px 置中；hover 樣式只包在 `@media (hover: hover)`。
- 垂直 TDD：一個測試 → 執行看到 FAIL → 最少實作 → PASS → 下一個測試。重構不在迴圈內。不 mock 內部模組。
- Node 由 winget 安裝；若目前 shell 的 PATH 還沒有 `npm`，使用 `"C:\Program Files\nodejs\npm.cmd"`。
- 每個 commit 訊息結尾加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. **每日局完成後重新整理**，不可再次呼叫 `recordResult`（統計不得重複累計）→ 由 Task 7 的存檔欄位 `recorded` 與手動驗收步驟固定。
2. **漏玩一天後開啟頁面**，「目前連勝」必須顯示 0，即使 `recordResult` 那天從未被呼叫 → 由 Task 4 的 `displayStreak` 測試固定。
3. **裝置時區不是台灣**（例如 UTC−5），題號仍以台灣日期計算 → 由 Task 3 以 UTC 時刻建構 `Date` 的測試固定。
4. **localStorage 會丟例外或內容損毀**（Safari 無痕、手動改壞 JSON）→ 遊戲仍可玩、統計重設 → 由 Task 6 的手動驗收步驟固定。
5. **Modal 開著時按鍵盤**，或用**數字小鍵盤**輸入 → Modal 開著時忽略遊戲按鍵；`Numpad0–9` 等同數字鍵 → 由 Task 6、Task 8 的手動驗收步驟固定。

- [ ] **Step 6: `randomSecret(4, rng)` 以固定序列 rng 產生可預期結果**

```js
const seq = (...xs) => { let i = 0; return () => xs[i++ % xs.length]; };
it('builds a secret from injected rng', () => {
  expect(randomSecret(4, seq(0, 0, 0, 0))).toBe('0123');
});
```

實作方式：從 `'0123456789'` 的剩餘池中以 `Math.floor(rng() * pool.length)` 取出，取出後移除（因此全為 0 的 rng 會得到 `0123`）。

### Task 3: 每日題號與答案

**Files:**
- Create: `src/daily.js`、`tests/daily.test.js`

**Interfaces:**
- Consumes: `randomSecret(length, rng)`（Task 2）
- Produces:
  - `DAILY_EPOCH = '2026-10-16'`（台灣日期字串；部署當天於 Task 9 改為實際上線日）、`DAILY_LENGTH = 4`、`DAILY_MAX = 10`
  - `dailyNumber(date: Date, epoch: string = DAILY_EPOCH) -> number`
  - `dailySecret(n: number) -> string`
  - `msUntilNextDay(date: Date) -> number`（距離下一個台灣 00:00 的毫秒數）

測試一律傳入明確的 `epoch = '2026-10-16'`，以 `new Date(Date.UTC(...))` 建構時刻，因此不受執行環境時區影響。

- [ ] **Step 1: 上線日台灣 00:00（`Date.UTC(2026, 9, 15, 16, 0)`）→ `1`**
- [ ] **Step 2: 台灣 2026-10-16 23:59（`Date.UTC(2026, 9, 16, 15, 59)`）→ `1`；台灣 2026-10-17 00:00（`Date.UTC(2026, 9, 16, 16, 0)`）→ `2`**
- [ ] **Step 3: 台灣 2026-11-15 12:00 → `31`**

實作：`Math.floor((date.getTime() + 8 * 3600e3) / 864e5)` 減去 `Date.parse(epoch + 'T00:00:00Z') / 864e5`，再加 1。

- [ ] **Step 4: `dailySecret(7) === dailySecret(7)`，且 `dailySecret(1..60)` 每個都是 4 位數、不重複數字，並且至少有 50 個不同的值**

實作：使用 mulberry32 種子亂數，種子為 `n * 2654435761 >>> 0`，傳給 `randomSecret(DAILY_LENGTH, rng)`。演算法上線後不可修改，否則當天的答案會改變。

```js
function mulberry32(a) {
  return () => {
    a |= 0; a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

- [ ] **Step 5: `msUntilNextDay`：台灣 23:59:00 → `60000`；台灣 00:00:00 → `864e5`**
- [ ] **Step 6: 全綠後 commit** `feat: add daily puzzle numbering and seeded secrets`

- [ ] **Step 2: 輸 → `played 1, wins 0`、`dist` 最後一格 +1、`best` 不變**

- [ ] **Step 4: `best` 取最小值：先 5 次、再 3 次 → `3`；之後 7 次 → 仍是 `3`**

- [ ] **Step 8: 沒有 `dayNumber`（練習）→ 連勝欄位維持不變**
- [ ] **Step 9: `displayStreak`：`lastWinDay` 是 4、`currentStreak` 是 3 → today 4 為 `3`、today 5 為 `3`（今天還沒玩）、today 6 為 `0`**
